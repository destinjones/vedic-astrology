# Blender asset pipeline

Everything in `assets/3d/` is generated by these scripts, so art can be regenerated or restyled at any time.
Tested with Blender 5.2 (Microsoft Store build) and Cycles OptiX on an RTX 3060.

## Regenerating

From PowerShell in this folder:

```powershell
.\run.ps1 render_grahas.py 1024 192        # size, samples, optional comma-separated names
.\run.ps1 render_wheel.py 2048 192         # size, samples, optional "top" or "hero"
.\run.ps1 render_medallions.py 512 96
.\run.ps1 render_backgrounds.py 1 128      # scale, samples, optional "plates,sky,hero"
.\run.ps1 export_gltf.py 2048              # after render_wheel.py; texture width, optional names
python build_manifest.py
```

`run.ps1` waits for Blender to finish and writes logs to `.logs/`. The Store build only starts through
`blender-launcher`, which discards console output, so the scripts log to a file themselves.
Fonts come from Windows (Georgia, Segoe UI Symbol).

## Conventions

`assets/3d/manifest.json` lists every asset, plus how to map a sidereal longitude onto the wheel image and the 3D models.
In short: 0° sidereal Aries is at 3 o'clock, longitude runs counterclockwise, and in three.js a longitude maps to
`(r*cos(lon), h, -r*sin(lon))`.

The wheel's divisions are computed from longitude (rashi 30°, nakshatra 13°20′, pada 3°20′), so graha markers placed
from engine output line up with the art. The star field and nebula are decorative procedural art, not a star catalogue.
